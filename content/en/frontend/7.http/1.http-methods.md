## Question

What HTTP methods exist and how do they differ from each other?

## Short answer

HTTP methods describe the **intent** of a request against a resource: `GET` — retrieve, `POST` — create/perform an action, `PUT`/`PATCH` — update, `DELETE` — remove, `HEAD`/`OPTIONS` — service methods.

## Detailed answer

- **`GET`** — retrieves a resource. Must not change server state (a safe method), can be cached, parameters are passed in the URL.
- **`POST`** — creates a new resource or performs an action that doesn't fit other methods. The request body can be anything.
- **`PUT`** — fully replaces a resource at a known URL (idempotent: calling it again with the same data produces the same result).
- **`PATCH`** — partially updates a resource (not required to be idempotent).
- **`DELETE`** — removes a resource.
- **`HEAD`** — same as `GET` but without a response body: used to check whether a resource exists or to inspect headers.
- **`OPTIONS`** — asks which methods a resource supports; browsers send it automatically as a preflight request before "non-simple" CORS requests.

Key properties of each method:

| Method  | Safe | Idempotent | Request body |
|---------|:----:|:----------:|:-------------:|
| GET     | ✅ | ✅ | no |
| POST    | ❌ | ❌ | yes |
| PUT     | ❌ | ✅ | yes |
| PATCH   | ❌ | ❌ | yes |
| DELETE  | ❌ | ✅ | usually not |

## Example

```js
// Get the list of users
await fetch('/api/users')

// Create a user
await fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify({ name: 'Alice' })
})

// Fully replace a user
await fetch('/api/users/1', {
  method: 'PUT',
  body: JSON.stringify({ name: 'Alice', age: 30 })
})

// Partially update a user
await fetch('/api/users/1', {
  method: 'PATCH',
  body: JSON.stringify({ age: 31 })
})

// Delete a user
await fetch('/api/users/1', { method: 'DELETE' })
```
