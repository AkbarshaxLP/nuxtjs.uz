## Question

How do the `PUT` and `PATCH` methods differ?

## Short answer

`PUT` replaces the entire resource — the client must send the full object representation. `PATCH` updates only the fields that were sent, leaving the rest unchanged.

## Detailed answer

- **`PUT`**: the server expects the **full object**. If a field is omitted, it may be cleared or reset to a default value — because the server treats the request as "here's the resource's entire new state".
- **`PATCH`**: the server applies a **partial** change — a set of instructions or an object with the changed fields. The rest of the resource is left untouched.

On idempotency:

- `PUT` is idempotent: sending the same request again produces the same result.
- `PATCH` is generally **not required** to be idempotent (e.g. if the body is an instruction like "increment the counter by 1", calling it again changes the result).

## Example

```js
// PUT — you must send ALL of the user's fields,
// otherwise omitted fields may be wiped out
await fetch('/api/users/1', {
  method: 'PUT',
  body: JSON.stringify({ name: 'Alice', age: 30, email: 'a@mail.com' })
})

// PATCH — it's enough to send just what's changing
await fetch('/api/users/1', {
  method: 'PATCH',
  body: JSON.stringify({ age: 31 })
})
```
