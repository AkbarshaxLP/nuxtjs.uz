## Savol

Mahsulot analitikasi (Google Analytics, Amplitude) bilan performance-metrikalar/RUM (Web Vitals) o'rtasidagi farq nimada va nega frontend-jamoasi uchun ikkalasi ham muhim?

## Qisqa javob

Mahsulot analitikasi (GA, Amplitude) "foydalanuvchilar mahsulotda nima qilmoqda" degan savolga javob beradi — bosishlar, o'tishlar, konversiya voronkalari. Performance-metrikalar va RUM (Web Vitals: LCP, INP, CLS) esa "mahsulot haqiqiy foydalanuvchilarda qanchalik tez va tezkor ishlaydi" degan savolga javob beradi. Birinchisi xatti-harakat haqida, ikkinchisi bajarilish tezligi/sifati haqida, va ikkala kategoriya ham frontend-jamoasiga turli qarorlar uchun kerak.

## Batafsil javob

**Mahsulot analitikasi (Google Analytics, Amplitude, Mixpanel, Yandex.Metrika)**:

- **Foydalanuvchi xatti-harakati hodisalarini** to'playdi: sahifa ko'rishlar, tugmalarni bosish, formalarni to'ldirish, savatga qo'shish.
- **Voronkalar** (funnels) quradi — nechta foydalanuvchi landing sahifadan buyurtma rasmiylashtirishgacha yetib bordi va qaysi bosqichda tushib qoladi, **kohort tahlili**, retention.
- Mahsulot/biznes savollariga javob beradi: "tugmaning qaysi varianti yaxshiroq konvert qiladi" (A/B-testlar), "eng qimmatli foydalanuvchilar qayerdan kelmoqda", "qaysi feature nopopulyar va nega".
- Product-menejerlar, marketing, dizaynerlar tomonidan ishlatiladi — lekin hodisalar va razmetkani (data layer, `track()`-chaqiruvlari) sozlash odatda frontend-dasturchilarning javobgarligi.

**Performance/RUM metrikalari (Web Vitals)**:

- Brauzer API'lari (`PerformanceObserver`) orqali to'g'ridan-to'g'ri haqiqiy tarmoq/qurilma sharoitlarida **haqiqiy foydalanuvchilardan** yig'iladi — bu **RUM (Real User Monitoring)** deb ataladi, sintetik laboratoriya o'lchovlariga (CI mashinasida belgilangan sharoitlarda Lighthouse) qarama-qarshi o'laroq.
- Asosiy **Core Web Vitals** metrikalari:
  - **LCP** — asosiy kontentning chizilish tezligi.
  - **INP** — foydalanuvchi harakatlariga javob berish tezkorligi.
  - **CLS** — vizual barqarorlik (razmetka "sakraydimi" yoki yo'q).
- Muhandislik savollariga javob beradi: "so'nggi relizdan keyin sahifa sekinlashdimi", "foydalanuvchilarning necha foizida LCP yomon va bu ottok bilan korrelyatsiya qiladimi", "sekin uchinchi tomon skripti INP'ga ta'sir qiladimi".
- Google Core Web Vitals'ni qidiruvda **reyting omili** sifatida ishlatadi, shu sababli bu nafaqat UX, balki SEO/biznes-metrika masalasi ham.

**Nega ikkalasi ham muhim**. Performance-metrikalarsiz analitika konversiyaning nega pasayganini *tushuntirmaydi* — ko'pincha sabab shundaki, sahifa bir soniyaga sekinroq yuklana boshlagan, va bu tezlik metrikalari bilan solishtirilmasa, sof xatti-harakat hodisalarida ko'rinmaydi. Mahsulot analitikasisiz performance-metrikalar esa *biznesga ta'sirini* ko'rsatmaydi — LCP 200ms'ga yaxshilandi, lekin bu haqiqatan konversiya yoki retention'ga ta'sir qildimi, noma'lum. Amalda jamoalar ikkala ma'lumotlar to'plamini **korrelyatsiya qiladi**: masalan, GA/Amplitude'da LCP'si yomon foydalanuvchilar segmentini belgilaydi va ularning konversiyasini LCP'si yaxshi segment bilan solishtiradi.

## Misol

```js
// Mahsulot analitikasi: "savatga qo'shdi" hodisasi
gtag('event', 'add_to_cart', {
  currency: 'USD',
  value: 49.99,
  items: [{ item_id: 'SKU123', item_name: 'Wireless Mouse' }],
})
```

```js
// RUM: Web Vitals'ni yig'ish va sahifa konteksti bilan birga yuborish,
// keyinchalik mahsulot metrikalari bilan solishtirish uchun
import { onLCP, onINP, onCLS } from 'web-vitals'

function report(metric) {
  const payload = {
    name: metric.name,        // 'LCP' | 'INP' | 'CLS'
    value: metric.value,
    id: metric.id,
    page: location.pathname,
  }
  navigator.sendBeacon('/rum-collector', JSON.stringify(payload))
}

onLCP(report)
onINP(report)
onCLS(report)
```
